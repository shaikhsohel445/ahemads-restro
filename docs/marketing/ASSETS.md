# Brand and product assets — Ahemad's Restro

Inventory of every logo, icon, screenshot and marketing graphic in this
repository, how each one is made and where it is used. Everything here is
generated by code in `scripts/assets/` (package `@ahemads-restro/asset-tools`),
so any asset can be rebuilt after a change instead of being edited by hand.

Sizes are pixel dimensions (SVGs: their `viewBox`). Paths are relative to the
repository root; `apps/web/public/` is served from the site root, so
`apps/web/public/brand/logo.svg` is `/brand/logo.svg` on the website.

## 7. Usage guidelines

These are guidelines for using the files above consistently.

- **Use the files as generated.** Do not redraw, stretch, rotate, add
  effects to, or re-type the logo. Scale proportionally only.
- **Do not recolour.** Use `logo.svg`/`logo-compact.svg` on light
  backgrounds, the `-dark` variants on dark backgrounds, and the `-mono`
  variants (charcoal or white) where only one colour is possible.
- **Clear space.** Keep empty space around the logo of at least the height
  of the mark's gold knob on every side, and more where possible. Do not
  place the logo on busy photographs; use `mark-mono-white.svg` or a solid
  emerald panel instead.
- **Minimum sizes.** Full logo with tagline: about 160 px (or 35 mm) wide, so
  the tagline stays legible; below that use the compact logo, and below about
  100 px wide use the mark alone. The mark has dedicated 16 and 32 px
  versions for favicons; do not scale the large mark down to those sizes.
- **Arabic contexts.** The wordmark is Latin. In Arabic layouts keep the
  logo itself left-to-right (as the application and site do); only the
  surrounding layout mirrors.
- **Screenshots.** Use them as captured. Do not edit numbers, add features
  that do not exist, or combine them with invented interface elements. If
  the product changes, regenerate them (section 8).
- **Attribution.** The logos are the Ahemad's Restro brand. Do not use the
  upstream "Nodedr" or "OrderRestro" names or images to market this
  product, other than to attribute the upstream project (see
  [NOTICE](../../NOTICE)).

## 8. Regenerating

Prerequisites: dependencies installed (`pnpm install`), Google Chrome
installed locally (`CHROME_PATH` to override its location; the default is
the macOS path), and nothing else using ports 8787 and 1995.

**Logos and icons** (no running app needed):

```bash
pnpm --filter @ahemads-restro/asset-tools brand
```

**Screenshots** — always against a fresh *local* database; `demo-data.mjs`
refuses to run against any API that is not on `localhost`/`127.0.0.1`:

```bash
# 1. reset the local D1 (deletes local data only)
rm -rf apps/api/.wrangler/state
pnpm --filter @ahemads-restro/types build
pnpm db:migrate:local
pnpm db:seed:local

# 2. start both Workers (separate terminals)
pnpm --filter @ahemads-restro/api dev            # :8787
pnpm --filter @ahemads-restro/web preview        # :1995

# 3. add realistic demo data through the API, then capture
node scripts/assets/demo-data.mjs
pnpm --filter @ahemads-restro/asset-tools screenshots
```

`WEB_URL` and `API_URL` override the default local addresses. Sign-in uses
the local seed account; nothing secret is captured.

**Marketing graphics** (after `brand` and `screenshots`):

```bash
pnpm --filter @ahemads-restro/asset-tools graphics
```

Scratch HTML goes to `scripts/assets/.tmp/` (git-ignored). Review every
regenerated image before committing it, and update this inventory if files
are added, removed or resized.
